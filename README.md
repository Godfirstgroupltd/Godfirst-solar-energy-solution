## 1. Technical Stack

- **Framework:** Next.js 14 (App Router, Server Components & Dynamic Route Handlers)
- **Language:** TypeScript 5 (Strict Mode)
- **Styling & Tokens:** Tailwind CSS with Brand Bible CSS variables
- **Icons:** Lucide React (strictly adhering to brand safety rules — no sun, bulb, or cross icons)
- **Database, Auth & Storage:** Supabase (PostgreSQL, Row Level Security, Storage Buckets)
- **Authentication:** Google OAuth 2.0 with single-admin server-side email verification
- **Typography:** Sora (Headings) & Inter (Body & Ultra-Light Division Caps) via `@import` & CSS variables
- **SEO & Compliance:** OpenGraph, Twitter Cards, LocalBusiness JSON-LD, `sitemap.ts`, `robots.ts`, WCAG AA accessibility

## 4. Supabase Setup Guide

### Step 1: Create a Supabase Project
1. Log in to [Supabase](https://supabase.com) and click **"New Project"**.
2. Select your organization and choose a region close to Nigeria (e.g., `Europe (London)` or `Europe (Frankfurt)` for low latency to West Africa).
3. Set your database password securely.

### Step 2: Run SQL Migrations
1. In your Supabase dashboard, navigate to the **SQL Editor**.
2. Open the file `supabase/migrations/20261105000000_init.sql` from this repository.
3. Paste the contents into the SQL Editor and click **Run**.
   - This creates all tables (`leads`, `services`, `packages`, `projects`, `blog_posts`, `testimonials`, `site_settings`).
   - Enables Row Level Security (RLS) on all tables.
   - Enforces the **Single-Admin Rule**: only `auth.jwt()->>'email' = 'godfirst.groupltd@gmail.com'` can write/update/delete.
   - Sets up the `site-media` storage bucket.

### Step 3: Run Seed Data (Optional)
1. Open `supabase/seed.sql` and run it in the SQL Editor to populate realistic placeholder records.

## 5. Google OAuth 2.0 Setup

To ensure strict single-admin security:
1. Go to the [Google Cloud Console](https://console.cloud.google.com/).
2. Create a new project or select an existing one.
3. In **APIs & Services > Credentials**, create an **OAuth 2.0 Client ID** (Web application).
4. Under **Authorized redirect URIs**, add:
   - For local development: `https://<YOUR-SUPABASE-PROJECT-REF>.supabase.co/auth/v1/callback`
5. Copy the **Client ID** and **Client Secret**.
6. In your Supabase dashboard, go to **Authentication > Providers > Google**:
   - Turn **Google Enabled** to `ON`.
   - Paste the **Client ID** and **Client Secret**.
   - Save the configuration.

> **Single-Admin Enforcement:** When someone logs in with Google OAuth, both our Next.js middleware and PostgreSQL RLS verify that `user.email === 'godfirst.groupltd@gmail.com'`. If any other Google account signs in, the session is immediately terminated and redirected to `/admin/login?error=unauthorized_email`.

## 6. Running Locally

### Prerequisites
- Node.js 18+ or 20+ installed.

### Steps
1. Clone or navigate to the workspace directory:
   ```bash
   cd "Godfirst solar energy solutoin"
   ```
2. Copy the environment variables:
   ```bash
   cp .env.example .env.local
   ```
3. Install dependencies:
   ```bash
   npm install
   ```
4. Start the development server:
   ```bash
   npm run dev
   ```
5. Open your browser and navigate to:
   - Public Website: [http://localhost:3000](http://localhost:3000)
   - Admin Command Center: [http://localhost:3000/admin](http://localhost:3000/admin)

## 7. Deploying to Vercel

1. Push this repository to GitHub or GitLab.
2. In [Vercel](https://vercel.com), click **"Add New Project"** and import the repository.
3. Under **Environment Variables**, add the variables from `.env.example`:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `ADMIN_EMAIL` (`godfirst.groupltd@gmail.com`)
   - `RESEND_API_KEY`
   - `NEXT_PUBLIC_SITE_URL` (e.g., `https://godfirstsolar.com`)
4. Click **Deploy**. Vercel will automatically run `next build` and deploy to global edge CDNs.
